## リリースを許可する前に必要な作業

1. **PCでの受け入れテスト:** Windows 11 x64、100/125/150/200%表示スケール、1366×768・1920×1080など。全画面、スクロール、文字化け、セーブ復元、ファイル選択、終了/再起動、レース進行、複数年度。
2. **Windowsの発行元・署名:** 対象の組織/個人と証明書の利用条件を確認。ビルドしたEXE/インストーラーのAuthenticode署名を検証し、署名済みハッシュを公開。署名なしの開発物と区別。
3. **パッケージ品質:** インストール/アンインストール、Portableからのセーブ引継ぎ、別Windowsユーザーでの隔離、Windows Defender等の警告の意味を確認。ソフトウェア更新手順を決める。
4. **UIと遊びやすさ:** 第三者に初見テスト。ボタン、ペース指示、体力、育成成長、部費、ランキングの理解、文字サイズ・色覚・キーボード操作を検証。
5. **ゲームバランス:** 複数の育成方針の自動対戦、意図せぬ必勝法・強化合宿の二重使用・過剰な資金増殖・保存データの改ざんによる不正進行がないか確認。
6. **商用と権利:** タイトル・大会・校名・画像/音声素材の権利確認。EULA/返金・個人情報・サポート窓口・法定表示・税務・各プラットフォームの販売規約を確認。
7. **デモと価格の検証:** 第三者テスト、ストア説明、操作動画・スクリーンショット、課金とキー配布方法。現在はライセンス認証/DRMなし。
8. **最終版のみリリース:** 上記ゲートをPASSさせ、所有者の明示的な販売承認を受けてタグ/Releaseを作成する。未検証をPASS扱いにしない。

[Windows desktop unsigned alpha workflow](https://github.com/shihuiarenjinba-png/game-stadium/actions/workflows/windows-build.yml) で成功した実行履歴を選び、Artifactsを確認すること。ここにあるEXEは開発・試用専用。**自動でユーザーへ販売されることはない。**

## 想定されるアーキテクチャ

- `src/engine.js`: ネットワーク不要の乱数・レース・資金・シーズン計算
- `src/app.js` / `src/styles.css`: 2Dの監督用ダッシュボード
- `desktop/main.cjs`: Electronサンドボックス、コンテンツ分離、ウィンドウ制御、外部通信遮断
- `scripts/make_icon.py`: オリジナルアイコン生成（Python標準ライブラリのみ）
- `.github/workflows/windows-build.yml`: 未署名Windows x64のビルド/成果物を取得
- `.github/workflows/test.yml`: Nodeのシミュレーション/UIスモークテスト

### 変更方針

`main` への直接pushは行わず、Draft Pull Requestで検証する。販売目的のコード署名・決済連携・価格表・公開Release等は別段階とする。
